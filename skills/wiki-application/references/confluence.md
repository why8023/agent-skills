# Confluence 更新参考

仅在确认目标是 Confluence 且相应接口可用时使用。本参考针对已支持 versioned content/storage 的部署；Cloud 与不同版本接口有差异，先读连接器 schema 或目标站点实际支持能力，不把某个 REST 路径套到所有 Wiki。

## 读取、备份与局部修改

- 读取页面的标识、标题、版本及 storage 正文；只需要渲染证据时可读取正文 DOM。保存必要响应字段，不输出整页 head、请求头、cookie、token 或原始认证对象。
- storage 与 DOM 是不同表示。不要将浏览器显示 HTML 直接回写为 storage；保留 `ac:`/`ri:` 宏、附件引用、锚点、属性与命名空间语法。
- 为改写区域建立稳定锚点，如栏目标题加祖先表格结构；有歧义则先查明。嵌套表格中的 `<tr>` 也会被简单正则命中，不能用全局行号或贪婪替换定位外层栏目。
- 使用适合该正文格式的结构解析器或已验证的源码区间定位，仅替换目标内容。解析器可能重新序列化宏、空白和属性，检查结构等价；需要逐字保留时检查非目标源码片段不变。不要为省事重建整张表。
- 生成后复核目标字段内容，并比较非目标正文、勾选/分类、评审栏、宏及附件引用。记录实际差异；只有目标栏目变化才进入发布。

## 图片和附件

- 备份正文引用与附件元数据；对本次替换的原图、原附件保留可恢复文件。新图采用与旧附件不同的文件名并明确映射引用，不删除旧版本。
- 上传后核对返回的附件身份、文件名及关联页面，必要时重新下载比较 SHA-256；页面引用必须指向实际存在的附件，检查空格、中文、转义和 URL 编码。
- 上传失败或超时，先读取附件列表、文件及版本判断是否成功，不重复上传同名附件。页面更新失败时保留新附件并记录其状态，不自动删除或改写旧附件。
- 备份有链接的原 Word/PDF 等材料；即使正文更新也保留仍有效的既有附件引用，不静默改为本地路径。

## 提交与冲突

- 发布前重新读取版本与 storage，确认仍与合并基线一致。存在新修改时重新生成差异；有内容冲突则停止写入并交代冲突点。
- 使用目标 API 实际要求的 ID、type、title、body 和 version。采用版本递增的接口时，只以刚核实的版本构造下一版本；发送精确 storage 正文并写简短版本说明。
- 冲突响应不通过猜版本、删除他人内容或不断增加版本号来绕过。
- 网络超时不代表失败。先读取当前版本、正文和附件，识别成功、未执行、冲突或仍不明。仍不明时保留拟发布文件和证据，报告待核验，不盲重试。
- 需要回退时读取最新页面后，仅恢复本次授权内容。历史备份不是覆盖后续人工修改的许可。

## 发布后

- 读取服务端新版本与正文并比较目标字段；再观察新鲜的渲染页面，核对表格、强调、图片和附件链接。
- 已打开标签可能仍显示旧缓存。按当前浏览器工具支持的刷新、导航或新观察机制确认版本；工具需用户刷新时明确说明具体操作，不把技术协助变成重复的发布批准。
- 全页截图不可用时可使用已支持的视口或分段截图，检查图片实际尺寸和覆盖区域，准确说明证据范围。不能把局部图称为完整页面核验。
- 分别记录服务器更新结果和显示核验结果。只完成前者时如实交付，不宣称全部完成。
