# 配置与维护

代码随 Skill 管理，机器配置与运行数据放在外部。当前入口支持 Windows 控制端和 PowerShell 7；远端浏览器只需 Chromium 扩展。其他控制端需要另行准备执行路径，不能因为 Skill 已分发就声称机器可用。

## 本机配置

默认配置文件为当前用户的 `.bsk/browser-skill-remote.json`。自定义位置使用当前进程的 `BSK_REMOTE_CONFIG`，服务管理器启动时也必须提供同一配置。配置包含：

| 字段 | 含义 |
| --- | --- |
| `ControllerMachine` | 已核实的 Windows 控制端机器名 |
| `TargetMachine` | 用户指定且已确认的远端机器名 |
| `ExpectedDeviceId` | `daemon devices --json` 中已确认属于目标浏览器的设备 ID |
| `ExpectedBrowser` | 已确认的浏览器类型，如 `edge` |
| `BskExecutable` | 控制端 bsk 的绝对路径 |
| `BskHome` | 专用 daemon 的外部运行目录 |
| `Listen` | 本入口使用 `127.0.0.1` |
| `Port` | daemon 的本地监听端口 |
| `PublicUrl` | 已配置 TLS 代理提供的 `wss://.../extension` 地址 |

配置可以额外登记计划任务名称、运行账号等维护信息。不要在配置中保存配对秘密或设备令牌；这些由 bsk 的专用运行目录管理。目录与配置限制为运行用户和 SYSTEM 可访问。安装 Skill 不会自动创建或更改机器配置。

已有连接先复用原来的 bsk、BSK_HOME 和授权。核实目标机器及浏览器配置文件后，通过专用入口的 `daemon devices --json` 登记设备 ID；不能从只有一个在线浏览器推断机器或配置文件归属。扩展重新安装、重置或重新配对后，重新确认映射。

初次安装、TLS 代理和配对使用 [官方原生远程连接指南](https://github.com/Tencent/BrowserSkill/blob/cli-v0.3.2/docs/remote-extension-connection.md)。扩展向控制端发起 WSS，控制端 CLI 使用本机 IPC。控制端与远端无需另一个 AI Agent。

配对链接含一次性秘密，只写入私有文件交给用户在目标扩展保存，不打印到聊天、日志或 Git。成功后删除该一次性文件。浏览器已有授权应由扩展自动续期，不在每个任务开始时重新配对。

## 服务管理

现有 Windows 计划任务的 action 使用 PowerShell 7，并指向此 Skill **已安装位置**的 `scripts/start-server.ps1`。运行账号应与 CLI 和外部配置的用户一致。沿用已有触发器、重试策略及权限；在启动脚本迁移前导出任务备份，核对没有活动会话后再切换并验证实际进程。

新配置可采用用户登录触发和每分钟重复触发，运行中忽略重复启动。只配置失败重试不等于实际恢复已验证；需要观察自然触发是否启动正确进程。任务前台运行 bsk server，不把它当遗留进程清理。

更新 Skill 后核验代码文件与任务引用，已有进程继续运行。需要重启时，只维护本次专用服务，先检查活动会话并保留授权目录。移除 Skill 前先停止或迁移引用它的服务任务。

## 状态与恢复

`discover` 会交叉检查授权记录和当前 daemon 的浏览器列表。授权记录说明设备被批准过，HTTP 未认证请求返回 401 说明认证入口可达，实际网页操作成功才说明浏览器任务可执行。

- 配置缺失或控制端不匹配：报告当前机器缺少入口，不创建另一份 daemon。
- 服务不可达：检查已登记的计划任务、IPC 权限及实际进程，保留拥有该服务的管理器。
- 授权缺失或过期：核对登记设备与扩展授权状态，确认需要重新配对后再处理。
- 浏览器离线：检查远端 Edge/Chrome、扩展及两端 Tailscale 状态。
- HTTP 可达但配对/WSS 失败：检查浏览器实际使用的代理路径、可信 TLS 证书和 WebSocket 转发。使用精确主机的代理例外，保留其他条目。

Tailscale Serve 使用独立端口时，回退只关闭该端口的转发，不能用 `tailscale serve reset` 清除其他服务。改动代理例外前备份，回退只移除本次新增条目。

## 受管更新与验证

源码在中央仓库 `skills/browser-skill-remote/`；个人环境通过已登记的 APM 清单固定完整提交，执行管理入口的 restore/check。不要改受管安装文件或绕过已有 APM 改用另一套安装工具。

验证包括配置外置、脚本哈希与固定源码一致、目标设备身份及连接状态、计划任务实际启动路径、一次授权范围内的真实网页操作和会话清理。新 Agent 的发现验证使用不带旧对话的请求，让它自行选择 Skill 和入口。

脚本的离线检查使用 `tests/self-check.ps1 -WorkDirectory <工作区内的绝对测试目录>`，通过隔离的 CLI 夹具验证设备匹配、失效状态、参数转发和环境恢复，不会操作真实浏览器。
