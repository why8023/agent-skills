# 偏好来源与诊断

这是从多轮真实调试中提炼的解释模型。源案例是企业工具门户，但稳定的是取舍方式；表中的反馈不构成新的通用限制。

## 反馈背后的目标

| 观察到的反馈 | 更稳定的偏好 | 容易误读成 | 优先检查或处理 |
| --- | --- | --- | --- |
| 白色版本比红色版本舒服，但纯白又普通 | 清爽的底面与明确的品牌重点同时存在 | 一律浅色，或往所有底面加淡红 | 色彩面积分配、字体层级、边界与材质细节 |
| 淡红铺满缺少大公司气质，红要明确，白要有设计 | 视觉角色清楚，整体强度受控 | 所有红色必须加深，所有组件必须白 | 主操作、选中、背景、辅助内容是否各有角色 |
| 图形左侧留白没有光效，像断开了 | 同一展示区的视觉和响应连续 | 去掉全部留白，或把动效铺满整页 | 背景所在祖先层、内边距、指针范围和坐标系 |
| 想要巧思，但不能明显地炫技 | 愿意保留技术感，注意力由任务决定 | 动效越少越好，或每块都必须会动 | 没有输入时是否安静，输入后反馈是否精准 |
| 连线不能断，又嫌加长后乱、成组太机械 | 主要关系完整，辅助纹理自然稀疏 | 永远不交叉，或线越长越一体化 | 主线与支线职责、端点、密度、文字避让 |
| 反复在交叉与不交叉之间选择 | 根据最终观感修正实现方案 | 把每次临时方案都累积成硬规则 | 优先修正杂乱和断裂，允许几何方案因场景改变 |
| 不需要存储阵列、逻辑单元等命名节点 | 主题细节可以存在，但不能增加无意义阅读负担 | 所有界面禁用节点或标签 | 装饰是否假装业务信息，标签是否帮助用户判断 |
| 选择下方功能时，光晕渐渐聚焦到相应图形 | 控件和内容的关联应有连续、可理解的反馈 | 每次悬停都追随鼠标 | 区分自由探索和有语义的选择目标 |
| 聚拢后的红心黄边很斑驳，分散配色不要动 | 聚焦态需要统一，其他已接受状态应保留 | 全局改色，或只把多个图层换成同一 RGB | 图层合成、背景、蒙版；让汇聚态交接给单一光源 |
| 快速上手放第一项更像统一介绍 | 顺序表达使用路径 | 所有产品默认打开帮助页 | 当前页面面对新用户还是熟练用户，主任务是什么 |

## 区分三种结论

- 稳定偏好：整体连续、品牌表达有重点、细节有来源、交互克制且能理解、已认可部分不被无关改动破坏。
- 场景做法：白银灰、品牌红、圆形光晕、芯片走线、门户介绍排首位。场景相符时再采用。
- 尚无依据的偏好：固定字体、固定圆角、所有页面必须浅色、必须有颗粒、一定不能交叉。不要凭这个案例替用户决定。

同一轴上的最新明确意见覆盖较早的试探。覆盖范围按用户的话限定，例如“只改汇聚态”不覆盖分散态。用户说“你用自己的方式解决”授权的是在目标与范围内选择实现方式。

## 常见症状的检查顺序

- 太白：先看是否缺乏层级、信息重点和表面差异，再考虑有限的品牌点缀。
- 太红或太花：先减少大面积覆盖与竞争焦点，保留应当鲜明的操作和品牌标识。
- 割裂：先看共同底面和几何边界，再看状态与事件范围；不要一开始提高装饰强度。
- 太乱：先让主次关系清楚，再减少装饰数量、重复簇和相互竞争的运动。
- 颜色脏、有色带：先隔离可见图层，检查合成结果；相同色值也会因重叠和底色不同产生不同观感。
- 没有巧思：先寻找内容之间已有但尚未表达的关系；精确的关联反馈通常比新增装饰更有价值。

这些顺序是诊断起点，不是忽视页面证据的固定流程。
